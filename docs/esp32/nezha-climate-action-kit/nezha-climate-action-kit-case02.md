# 案例二：城市噪音观察器

## 案例简介

校园中的交谈、脚步和车辆声音会随时间变化。本案例利用 **Nezha ESP32** 的板载麦克风读取声音强弱的相对值，在屏幕上显示声音状态，并在超过阈值时给出提示。学生通过采集、比较和调节阈值，学习声音感知与条件判断。

学生将通过搭建、编程和测试，把观测结果与模型的显示或动作联系起来，学习用数据解释现象。

通过本案例，学生可以结合课堂观察与工程实践，思考如何利用技术改善校园和城市环境。

## 教学目标

完成本案例后，学生能够：

1. 读取声音强弱数据，并区分相对读数与声压级。
2. 使用条件判断将读数分为不同状态。
3. 选择合适的提示方式，评价提醒对环境的影响。
4. 根据测试结果调整参数，经历“设计—编程—测试—改进”的工程实践过程。

## 课程引入

请学生回想图书馆与操场的声音差异：什么场景需要安静？能否设计一块会提醒大家轻声说话的提示牌？先讨论提醒方式，再通过测量确定阈值。

本节课中，我们将扮演“城市环境设计师”，搭建城市噪音观察器，用实际观测检验自己的设计。

## 学习探究

在开始搭建前，可以分组讨论以下问题：

1. 同样的声音在远处和近处，读数是否一致？
2. 为什么不能直接把传感器读数写成分贝？
3. 扬声器发出的提示音会不会被麦克风再次检测到？
4. 你会怎样记录测试条件，说明结果是否符合预期？
5. 如果把模型应用到真实环境，还需要考虑哪些因素？

## 程序设计

程序分为“启动初始化”和“循环运行”两个部分。

### 1. 启动初始化

<!-- 图片占位符：启动初始化程序截图 -->
<!-- 建议文件名：./images/urban-sound-observer-program-init.png -->

程序启动后将执行以下操作：

1. 先在安静和正常交谈环境读取数据，选择可区分两种状态的阈值。
2. 初始化屏幕与数据变量，避免沿用上一次运行的状态。
3. 在屏幕预定位置显示数据标签与初始运行状态。

主控盒屏幕的显示布局如下：

| 屏幕行 | 显示内容 |
| ---: | --- |
| 第 1 行 | 声音值 |
| 第 2 行 | 声音强弱相对值 |
| 第 3 行 | 运行状态 |
| 第 4 行 | 正常 / 请轻声 |

### 2. 循环检测与控制

<!-- 图片占位符：循环检测与控制程序截图 -->
<!-- 建议文件名：./images/urban-sound-observer-program-main.png -->

在 `forever` 循环中，系统会持续执行以下任务。

#### 循环判断

- 读取声音值；大于阈值时进入提醒状态，否则进入正常状态。

#### 状态反馈

- 在屏幕显示读数和状态；优先采用图标或灯光反馈。

### 3. 关键参数

| 参数 | 示例值 | 含义 | 调整建议 |
| --- | ---: | --- | --- |
| 声音阈值 | 待实机确认 | 非通用固定值，不使用未经确认的分贝单位 | 先测量再确定 |
| 提示间隔 | 待实机确认 | 使用声音提醒时增加冷却时间，减少自触发 | 按课堂效果调整 |

:::note
麦克风感知声音变化，程序读取当前编程环境提供的声音强弱数值，再与阈值比较。超过阈值时显示提醒，否则显示正常状态。本案例不假定双麦克风具有声源定位能力，也不把未经校准的数值标为 dB。
:::

## 运行测试

完成程序后，按以下顺序测试：

1. **启动检查**：连接设备并下载已验证程序，确认初始化状态与屏幕标签正确。
2. **保持安静，再正常交谈**：读数有变化，阈值设置合理时状态随之改变。
3. **改变发声距离**：记录距离变化对读数的影响。
4. **持续发声后恢复安静**：提醒能够解除，不反复自触发。
5. **复测与记录**：改变一个条件后重复测试，记录输入、输出与结果。

如果出现“一直处于提醒状态”，重新测量背景声音并调整阈值；检查提示音是否造成反馈。

如果出现“敲桌时读数异常”，将模型与振动源隔开，采用正常交谈声测试。

## 扩展挑战

### 挑战一：增加持续超标判断

只有声音连续超过阈值一段时间才显示提醒。比较增加判断前后，短促声音引起的误触发次数。

### 挑战二：统计提醒次数

创建提醒次数变量，每次从正常状态进入提醒状态时累加一次。讨论次数能反映什么，以及不能反映什么。

### 挑战三：设计分级灯光

设置多个声音等级，用不同颜色或图标反馈。明确每一等级的范围并测试边界。

### 挑战四：比较发声距离

保持发声方式相近，改变与麦克风的距离。比较读数，并讨论背景声音对结果的影响。

### 挑战五：改进提醒方式

比较图标、灯光与提示音三种反馈方式。观察提醒效果以及设备自身声音引起的干扰。

## 扩展知识

### 声音从哪里来？

物体振动可以产生声音，麦克风将声音变化转换为电信号，程序再读取扩展库提供的声音强弱数据。

### 为什么不能直接写成分贝？

声压级测量需要明确的参考量、采样处理和校准。普通课堂声音读数可以比较变化，但不能直接作为专业噪声检测结果。

### 什么是反馈干扰？

设备自己发出的提示音也可能被麦克风检测到。使用图标或灯光提示，或为声音提醒设置间隔，可以减少持续触发。
