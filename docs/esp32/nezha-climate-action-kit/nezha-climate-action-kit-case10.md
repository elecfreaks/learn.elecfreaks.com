# 案例十：智能低碳公交站

## 案例简介

城市公交站是人们绿色出行的重要公共设施，但在炎热或强光环境中，候车体验常常受到影响。本案例将温度检测、光照检测、自动降温、自动遮阳和 RFID 低碳出行打卡整合到一个积木公交站模型中。

学生将使用 **Nezha ESP32** 读取温湿度传感器和板载光敏传感器的数据：当温度达到设定值时，风扇自动启动；当光照达到设定值时，电机带动遮阳棚展开。乘客还可以使用 RFID 卡模拟公交卡打卡，系统会累计低碳出行次数，并在主控盒屏幕上实时显示温度、光照值和累计次数。

通过本案例，学生可以把环境感知、条件判断、变量计数与机械结构结合起来，思考如何利用技术改善城市公共空间并鼓励低碳出行。

## 教学目标

完成本案例后，学生能够：

1. 了解高温和强光对城市候车环境的影响，以及公共交通与低碳出行的关系。
2. 读取温度、光照和 RFID 检测结果，并在屏幕上显示数据。
3. 运用“如果……否则……”条件判断控制风扇和遮阳棚。
4. 使用变量记录 RFID 打卡次数，理解变量初始化与累加的作用。
5. 根据测试结果调整温度、光照阈值，经历“设计—编程—测试—改进”的工程实践过程。

## 课程引入

炎热的夏天，人们在公交站等车时可能会遇到阳光直射、温度过高等问题。如果公交站能够感知周围环境，并自动打开风扇或遮阳棚，候车会不会更加舒适？如果乘坐公交的人还可以通过刷卡记录自己的低碳出行次数，又能否鼓励更多人选择公共交通？

本节课中，我们将扮演“城市公共设施设计师”，搭建一个会感知、会判断、会行动的智能低碳公交站。

## 学习探究

在开始搭建前，可以分组讨论以下问题：

1. 公交站在什么情况下需要启动风扇？
2. 遮阳棚应根据温度还是光照强度展开？为什么？
3. 不同教室或不同时间的光照值是否相同？怎样确定合适的阈值？
4. 如何避免同一张 RFID 卡停留在感应区时被连续计数？
5. 除温度和光照外，还可以采集哪些数据来改善候车体验？

## 搭建步骤

按照搭建说明完成公交站底座、站牌、活动遮阳棚、降温风扇、主控盒安装位和 RFID 刷卡区。

搭建时重点检查：

- 遮阳棚能够在 `0°` 与 `180°` 之间顺畅运动，不与其他积木干涉；
- 风扇叶片周围留有足够空间，可以安全旋转；
- 温湿度传感器保持通风，不被主控盒或积木完全遮挡；
- RFID 感应面朝上，便于放置和移开卡片；
- 所有连接线远离齿轮、转轴和风扇叶片。

## 程序设计

程序分为“启动初始化”和“循环运行”两个部分。

### 1. 启动初始化

<!-- 图片占位符：启动初始化程序截图 -->
<!-- 建议文件名：./images/smart-low-carbon-bus-stop-program-init.png -->

程序启动后将执行以下操作：

1. 隐藏屏幕标题栏，为数据显示留出更多空间。
2. 将变量 `Low-Carbon Trip Count` 设为 `0`。
3. 在屏幕第 1、3、5 行分别显示 `Temp:`、`Lux:` 和 `Low-Carbon Count`。

主控盒屏幕的显示布局如下：

| 屏幕行 | 显示内容 |
| ---: | --- |
| 第 1 行 | `Temp:` |
| 第 2 行 | 当前温度值 |
| 第 3 行 | `Lux:` |
| 第 4 行 | 当前光照值 |
| 第 5 行 | `Low-Carbon Count` |
| 第 6 行 | RFID 低碳出行累计次数 |

### 2. 循环检测与控制

<!-- 图片占位符：循环检测与控制程序截图 -->
<!-- 建议文件名：./images/smart-low-carbon-bus-stop-program-main.png -->

在 `forever` 循环中，系统会持续执行三项任务。

#### 温度控制风扇

- 读取 J1 接口温湿度传感器的温度值；
- 当温度 **大于或等于 26°C** 时，打开 J2 接口的风扇；
- 当温度低于 26°C 时，关闭风扇；
- 将当前温度显示在屏幕第 2 行。

#### 光照控制遮阳棚

- 读取主控盒的板载光敏传感器数值；
- 当光照值 **大于或等于 5000** 时，M1 电机以 30% 速度顺时针转到绝对角度 `180°`，展开遮阳棚；
- 当光照值低于 5000 时，M1 电机以 30% 速度逆时针转到绝对角度 `0°`，收回遮阳棚；
- 将当前光照值显示在屏幕第 4 行。

#### RFID 记录低碳出行

- 当 RFID 传感器检测到卡片时，将 `Low-Carbon Trip Count` 增加 `1`；
- 程序等待 `500 ms`，减少一次刷卡产生的重复计数；
- 将累计次数显示在屏幕第 6 行。

### 3. 关键参数

| 参数 | 示例值 | 含义 | 调整建议 |
| --- | ---: | --- | --- |
| 温度阈值 | 26°C | 达到该温度时启动风扇 | 可根据教室温度改为 25～30°C |
| 光照阈值 | 5000 | 达到该数值时展开遮阳棚 | 先观察现场数值，再设置合适阈值 |
| 电机速度 | 30% | 遮阳棚运动速度 | 速度过快可能使结构晃动 |
| 展开角度 | 180° | 遮阳棚展开位置 | 应根据实际结构校准 |
| 收回角度 | 0° | 遮阳棚初始位置 | 上电前确认机械零位 |
| 刷卡等待时间 | 500 ms | 简单降低重复计数概率 | 卡片应刷过后及时移开 |

:::note
程序中的光照值是主控盒光敏传感器返回的相对数值，不应直接视为经过标定的标准照度（lx）。建议学生先记录弱光与强光条件下的读数，再确定适合当前环境的阈值。
:::

:::caution
当前程序只在识别卡片后等待 500 ms。如果卡片长时间停留在感应区，计数仍可能继续增加。测试时请采用“刷卡后立即移开”的操作方式；进阶任务可增加“等待卡片离开后再允许下一次计数”的防重复逻辑。
:::

## 运行测试

完成程序后，按以下顺序测试：

1. **屏幕测试**：启动设备，确认屏幕显示温度、光照和低碳出行次数三个项目。
2. **温度测试**：用手掌短暂包围温湿度传感器，或在教师指导下改变其周围温度，观察温度达到 26°C 后风扇是否启动。
3. **光照测试**：用手遮挡光敏传感器，再使用台灯增加光照，观察遮阳棚是否在阈值两侧收回和展开。
4. **刷卡测试**：将 RFID 卡靠近感应区后立即移开，观察累计次数是否增加 1。
5. **综合测试**：同时改变温度和光照并进行刷卡，确认三项功能能够独立、连续运行。

如果遮阳棚的展开与收回方向和预期相反，可以交换程序中的电机方向，或根据模型的实际零位调整 `0°` 与 `180°`。

## 案例演示

程序运行后，智能低碳公交站可以根据环境变化自动响应：

- 高温时，风扇自动启动，为候车区模拟通风降温；
- 强光时，遮阳棚自动展开，为乘客模拟遮阳；
- 环境恢复后，风扇关闭，遮阳棚收回；
- 乘客刷 RFID 卡后，低碳出行次数增加；
- 屏幕持续显示温度、光照和累计次数。

## 扩展挑战

### 挑战一：显示湿度

读取温湿度传感器的湿度值，并在屏幕上增加湿度显示。

### 挑战二：防止重复刷卡

增加一个“允许计数”变量。只有在卡片离开感应区后，下一次刷卡才可以再次计数。

### 挑战三：减少频繁启停

为风扇设置两个温度阈值，例如温度达到 27°C 时启动，降到 25°C 时关闭，体验“回差控制”如何让系统运行得更稳定。

### 挑战四：设计低碳积分

为每次公交出行设置积分，并在达到指定次数后通过屏幕、RGB 灯或扬声器给予反馈。

### 挑战五：接入 IoT 数据看板

将温度、光照和低碳出行次数上传到 IoT 平台，比较不同时段的数据变化，并用图表说明公交站的使用情况。

## 扩展知识

### 为什么公共交通有助于低碳出行？

公交车可以在一次行程中运送多名乘客。当更多人选择公共交通、步行或骑行时，人均出行所需的能源和产生的排放通常可以降低。智能公交站不仅提供出行服务，还可以通过环境监测、节能控制和信息提示改善乘客体验。

### 什么是环境阈值？

阈值是触发系统采取行动的临界值。在本案例中，26°C 是风扇的启动阈值，5000 是遮阳棚的光照触发值。阈值并不是在所有场景中都固定不变，学生需要通过观察、测量和测试，为不同环境选择合适的数值。

### 从“感知”到“行动”

智能系统通常包含三个基本环节：

1. **感知**：传感器获取温度、光照或卡片状态；
2. **判断**：程序将数据与阈值进行比较；
3. **行动**：风扇、电机和屏幕根据判断结果作出响应。

智能低碳公交站把这三个环节组合在同一模型中，使学生能够直观看到数据如何驱动真实动作。
