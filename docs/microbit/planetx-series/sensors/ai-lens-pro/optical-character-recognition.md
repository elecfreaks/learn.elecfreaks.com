# 案例：AI 文字口令提示牌

读取纸上的文字，用口令切换提示图案

## 案例简介

把写有“GO”或“STOP”的纸牌放在镜头前，设备能否读出文字并作出回应？本案例用 AI Lens Pro 的光学字符识别（OCR）功能读取印刷文字，再在 micro:bit 上显示箭头或停止图案。

这些纸牌是用于 OCR 测试的普通文字纸牌，不是配套交通符号卡片。项目重点是文字内容的获取、匹配和识别失败处理。

## 教学目标

1. 了解 OCR 读取图像中文字的作用。
2. 学习判断文字是否存在，并获取文字内容。
3. 比较字符串匹配与文字存在判断。
4. 观察字体、光照、倾斜和空白字符对识别结果的影响。

## 硬件连接

1. 关闭电源，安装 micro:bit，将 AI Lens Pro 接到扩展板的 **IIC 接口**。
2. 固定镜头，让文字纸牌能够正对镜头，尽量减少反光和倾斜。
3. 用 USB 数据线连接 micro:bit 与电脑，以便查看文字输出。
4. 先开启 AI Lens Pro，再运行主控程序。

## 软件准备

本案例使用 **Microsoft MakeCode** 图形化编程平台。

1. 打开 [MakeCode 网站](https://makecode.microbit.org/)，新建“AI 文字口令提示牌”项目。
2. 在 **扩展（Extensions）** 中搜索 `planetX-AI`，添加 AI Lens Pro 扩展库。
3. 在工具栏中找到 **AI Lens Pro** 的基础设置、OCR 积木，以及 micro:bit 的文本比较、串口与 LED 图案积木。
4. 下载并连接设备后，打开 MakeCode 的设备数据查看功能，观察 OCR 原始文字。

## 积木使用方法

### 1. 判断是否识别到文字

初始化并切换到 **OCR**。每轮先使用 **从 AI 摄像头 Pro 获取一帧图像**，再用 **图像中包含文字** 判断有效结果。

### 2. 读取和匹配内容

使用 **从图像中获取文字的内容** 保存到变量 **文字**，再与 `GO`、`STOP` 比较；也可用 **从图像中获取文字内容为 [文字]** 判断。精确匹配时，大小写、空格和换行都可能影响结果。

未检测到文字时，不把失败提示当作有效口令。先在串口核对实际返回内容，再决定是否需要去除首尾空白或统一大小写。

## 示例程序：文字口令切换图案

### 程序思路

读取一帧文字并输出到串口，再按完整内容匹配。`GO` 显示向前箭头，`STOP` 显示方框；其他文字显示问号，无文字时清屏。

### 显示设置

| OCR 结果 | LED 显示 |
| --- | --- |
| GO | 向前箭头 |
| STOP | 方框 |
| 其他有效文字 | 自定义问号 |
| 未识别到文字 | 清屏 |

### 程序搭建

以下文字为积木搭建逻辑：

```text
当程序启动
    初始化 AI Lens Pro
    切换功能为 OCR

重复执行
    从 AI Lens Pro 获取一帧图像
    如果 图像中包含文字
        设置 文字 = 从图像中获取文字的内容
        串口输出文字
        如果 文字 = "STOP"
            显示方框
        否则如果 文字 = "GO"
            显示向前箭头
        否则
            显示自定义问号图案
    否则
        设置 文字 = 空字符串
        清屏
    等待 300 毫秒
```

## 下载程序

1. 使用 USB 数据线连接电脑与 micro:bit，下载程序。
2. 开启摄像头并运行主控，打开设备数据查看界面。
3. 依次展示 GO、STOP 和其他文字，核对串口内容与图案，再撤走纸牌。

## 效果演示

摄像头读出 GO 或 STOP 后，micro:bit 显示对应图案；陌生文字显示问号，撤走文字纸牌后清屏。

## 学习衔接

建议先完成[桌面物品检查员](./object-recognition.md)，再进行本课。

比较上一课的物品类别名称与本课读出的原始文字；保留 GO、STOP 口令纸牌，后续可将图案提示迁移为小车启停指令。

下一课：[目标位置指示器](./object-tracking.md)。

## 思考与拓展

1. 为什么设备读出了文字，却可能没有触发对应图案？
2. 同一张纸牌倾斜、缩小或更换字体后，结果怎样变化？
3. 怎样处理识别结果中的首尾空格和大小写差异？
4. 能否将文字口令与图码内容作比较，设计两种信息输入方式？
