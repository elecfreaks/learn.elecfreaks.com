# 案例：AI 举手计数器

识别举手和放下动作，记录完成的动作次数

## 案例简介

课堂互动时，怎样让设备记录一次完整的举手动作？本案例用 AI Lens Pro 判断人体姿态，在“未举手”变成“举手”时计数一次，持续举手不会重复增加。

程序通过重新放下手臂来允许下一次计数，帮助我们理解持续状态与动作事件的区别。

## 教学目标

1. 学会检测人体姿态并判断举手状态。
2. 使用状态变量识别动作变化。
3. 为计数增加连续确认，减少识别抖动。
4. 处理人物离开画面和计数复位。

## 硬件连接

1. 关闭电源，安装 micro:bit，将 AI Lens Pro 连接到扩展板的 **IIC 接口**。
2. 固定镜头，让体验者的头部、躯干和手臂完整出现在画面中。
3. 在地面标记体验位置，测试时先让一人进入画面。
4. 先开启摄像头，再启动主控程序。

## 软件准备

本案例使用 **Microsoft MakeCode** 图形化编程平台。

1. 打开 [MakeCode 网站](https://makecode.microbit.org/)，新建“AI 举手计数器”项目。
2. 在 **扩展（Extensions）** 中搜索 `planetX-AI`，添加 AI Lens Pro 扩展库。
3. 在工具栏中找到 **AI Lens Pro** 的基础设置、人体姿态判断积木，以及 micro:bit 的数字显示和变量积木。
4. 核对当前固件支持的举手姿态选项。

## 积木使用方法

### 1. 检测人体与举手姿态

初始化并切换到**姿态识别**。每轮获取一帧图像，先使用 **图像中包含人体姿态**，再用 **从图像中获取的人体姿态为举手** 判断。

### 2. 读取姿态信息

可以读取人体姿态的名称、位置和关键节点坐标辅助观察。画面中多人同时出现时，默认查询中心人物；已学习姿态 ID 是类别编号，不能作为某个人的固定身份编号。

## 示例程序：一次举手只计数一次

### 程序思路

创建变量 **次数**、**可以计数**、**举手帧数**、**放下帧数**。先确认连续三帧非举手，再允许计数；连续三帧举手后加一并锁定，直到再次确认放下。

### 状态设置

| 输入状态 | 处理方法 |
| --- | --- |
| 连续三帧有人且未举手 | 允许下一次计数 |
| 连续三帧举手且允许计数 | 次数加一，锁定本次动作 |
| 持续举手 | 保持次数 |
| 未检测到人体 | 清空连续帧计数，等待重新放下确认 |

### 程序搭建

以下文字为积木搭建逻辑：

```text
当程序启动
    初始化 AI Lens Pro
    切换功能为姿态识别
    设置 次数 = 0，可以计数 = 0
    设置 举手帧数 = 0，放下帧数 = 0
    显示数字 0
当 A 键按下
    设置 次数 = 0，可以计数 = 0
    设置 举手帧数 = 0，放下帧数 = 0
    显示数字 0

重复执行
    从 AI Lens Pro 获取一帧图像
    如果 图像中包含人体姿态
        如果 人体姿态为举手
            举手帧数增加 1，设置 放下帧数 = 0
            如果 举手帧数 ≥ 3 且 可以计数 = 1
                次数增加 1，设置 可以计数 = 0
                显示次数
        否则
            放下帧数增加 1，设置 举手帧数 = 0
            如果 放下帧数 ≥ 3
                设置 可以计数 = 1
    否则
        设置 举手帧数 = 0，放下帧数 = 0，可以计数 = 0
    等待 100 毫秒
```

## 下载程序

1. 用 USB 数据线连接 micro:bit，下载程序。
2. 开启 AI Lens Pro 并启动主控，让体验者先放下手臂。
3. 反复举手、放下，核对次数；按 A 键清零。

## 效果演示

每完成一次“放下—举手”动作，次数增加一。持续举手不重复计数，离开画面后需要重新确认放下状态。

## 思考与拓展

1. 直接在“举手”条件中加一，为什么一次举手会被计算多次？
2. 三帧确认改成五帧后，快速动作还能被记录吗？
3. 如何用肩部和手腕关键点的相对位置辅助判断举手？
4. 能否设计一个按规定次数完成动作的互动挑战？
