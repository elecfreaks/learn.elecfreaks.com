# 案例二：摇杆操控——控制 PU 前后左右

## 案例简介

本案例是手柄遥控系列第二课。在案例一"按键发指令"的基础上，学习使用摇杆实时操控 PU 机器人前后左右移动。摇杆是一个会连续变化的传感器，前推、后拉、左拨、右拨会产生不同的数值，本课引导学生读取摇杆数值、用"死区"过滤抖动，并用 if 判断把摇杆方向翻译成 PU 的移动方向，体验"连续量→方向判断"的实时遥控方式，为下一课摇杆转向做铺垫。

## 课程目标

1. 认识摇杆传感器：理解摇杆前后/左右两个轴会输出连续数值（约 -1~+1），居中时接近 0；

2. 掌握"死区"概念：理解为什么摇杆轻微抖动需要设定阈值过滤，避免机器人误动作；

3. 学会用 if 多分支判断，把摇杆的前后/左右数值翻译成 PU 的前进、后退、向左、向右四种移动；

4. 通过实时操控练习，体会"连续输入—判断—执行"的控制逻辑，提升程序调试与观察能力。

## 课程引入

上节课我们按下 B1、B2，PU 就"一令一动"——这种控制一次只能做一个动作。可真正的遥控车不是这样的：推一下摇杆，车就往前跑；往后拉，车就后退；摇杆回到中间，车就停下。今天我们要把摇杆变成 PU 的"方向盘"和"油门"：往前推，PU 前进；往后拉，PU 后退；往左拨、往右拨，PU 左右移动。摇杆是怎么"告诉"PU 方向的？PU 又是怎么知道该往哪走的？动手试试吧！

## 学习探究

1. 旧知巩固：回顾案例一的双机配对三步（设置无线电组 → 初始化按键/启用遥控模式 → 用 if 响应指令）。提问："要让 PU 前进，用哪个方向参数？"复习 MoveDirection 方向选项。

2. 新知识学习——摇杆的两个轴：摇杆内部有两个互相垂直的电位器，一个管前后（我们叫它 speed 轴）、一个管左右（turn 轴）。拨动摇杆时，micro:bit 读到的数值会在约 -1~+1 之间变化：前推接近 +1、后拉接近 -1、居中接近 0。演示手柄端「读取摇杆 speed 值 / turn 值」积木，观察数值随拨杆变化。

3. 新知识学习——死区与方向判断：摇杆停在中间时数值不是精确的 0，会有轻微抖动，如果直接判断，PU 会自己乱走。因此设定阈值 0.3：只有读数大于 0.3（明显前推）或小于 -0.3（明显后拉）才响应，0.3 以内的抖动全部忽略，这个阈值叫"死区"。机器人端用 4 个 if 分支把前后/左右数值翻译成 4 个移动方向。

4. 动手验证：烧录两端程序后，前推摇杆观察 PU 前进 4 步；后拉后退；左拨/右拨左右平移；摇杆回中，PU 应保持不动——若 PU 仍抖动前进，检查死区 0.3 是否被正确保留。

## 课堂活动

在地面贴一个十字方向标，把 PU 放在中心。教师发口令"前进两格""后退一格""向右平移一格"，操作员拨动摇杆执行，观察员记录是否走对方向、是否一次到位，比一比哪个小组配合最默契、操作最跟手。

进阶挑战：把直行步数从 4 改成 6，感受 PU 走得更远；再把死区 0.3 改成 0.1，观察会发生什么（摇杆轻轻一动 PU 就会响应），体会死区大小的作用。

## 总结分享

教师总结：摇杆把"人的意图"变成了连续数值（前后轴、左右轴），机器人端用"死区 + 多分支 if"把它翻译成 4 个方向动作——连续输入加条件判断，就实现了像遥控车一样的实时操控。下节课我们将改造方向分支：当 PU 遇到墙角想转弯时，把"平移"换成"原地转向"，让 PU 学会掉头。
