案例八：积水警戒闸门

案例简介​

暴雨后道路低洼处可能出现积水，模型如何提醒人们注意？本案例用水位传感器读取积水状态，Nezha ESP32 在读数超过警戒阈值时升起警戒杆，并通过屏幕和提示音提醒。学生通过模拟实验理解阈值判断与安全状态联动。

学生将通过搭建、编程和测试，把观测结果与模型的显示或动作联系起来，学习用数据解释现象。

通过本案例，学生可以结合课堂观察与工程实践，思考如何利用技术改善校园和城市环境。

教学准备​

名称数量用途
城市气候守护套装1 套搭建积水警戒闸门模型
Nezha ESP321 个运行程序、读取数据并显示信息
套装水位传感器按实际配置完成本案例对应的检测、控制或联网任务
浅水容器、少量清水与干燥垫按实际配置完成本案例对应的检测、控制或联网任务
RJ11 连接线按实际需要连接兼容的外接模块；纯板载功能无需外接
电脑及数据线1 套编写、下载和调试程序

教学目标​

完成本案例后，学生能够：

  1. 观察水位传感器读数与浸水状态的关系。
  2. 建立正常与警戒两种状态，并控制闸门模型。
  3. 设计安全的测试流程并识别模型局限。
  4. 根据测试结果调整参数，经历“设计—编程—测试—改进”的工程实践过程。

课程引入​

提出情境：校园模型中的一段低洼道路积水了，如何提醒经过的人？先让学生描述警戒装置的形状和状态含义，再规定本案例“警戒杆升起”表示警戒；它不是开放通行的闸机。

本节课中，我们将扮演“城市环境设计师”，搭建积水警戒闸门，用实际观测检验自己的设计。

学习探究​

在开始搭建前，可以分组讨论以下问题：

  1. 同样的浸水深度，不同水质的读数会一样吗？
  2. 闸杆升起在本模型中表示警戒还是放行？
  3. 为什么水位下降后也应确认环境安全？
  4. 你会怎样记录测试条件，说明结果是否符合预期？
  5. 如果把模型应用到真实环境，还需要考虑哪些因素？

搭建步骤​

按照搭建说明完成积水警戒闸门的底座、主控安装位和相关功能结构。

搭建时重点检查：

  • 将主控、电源和电机固定在容器上方或远离容器的干燥区域。
  • 仅让模块允许接触水的探测部分接触水，不浸没接口和电子元件。
  • 标记正常与警戒两个机械位置，低速检查动作。

硬件连接​

关闭电源后，按照下表连接模块：

模块接口作用
水位传感器兼容传感器接口待确认感知接触水的状态
警戒杆电机电机接口、角度或限位方式待确认执行警戒动作
板载屏幕/可选扬声器板载警戒状态提示
提示

板载功能无需外接线。外接模块应按最终程序确认兼容接口；使用 IIC 模块时还应核对总线地址。接线时请对准接口方向，不要在设备通电时插拔模块。

程序设计​

程序分为“启动初始化”和“循环运行”两个部分。

备注

以下为教学逻辑建议稿。当前未提供本案例实际程序，接口编号、积木名称和控制参数须以实机验证结果为准；程序截图位置暂用明确标注的占位图。下方屏幕布局同样为建议方案。

1. 启动初始化​

程序启动后将执行以下操作：

  1. 先记录干燥与不同接触水状态的读数，确定警戒阈值。
  2. 初始化屏幕与数据变量，避免沿用上一次运行的状态。
  3. 在屏幕预定位置显示数据标签与初始运行状态。

主控盒屏幕的显示布局如下：

屏幕行显示内容
第 1 行水位值
第 2 行水位传感器读数
第 3 行运行状态
第 4 行正常 / 积水警戒

2. 循环检测与控制​

在 forever 循环中，系统会持续执行以下任务。

标定​

  • 先记录干燥与不同接触水状态的读数，确定警戒阈值。

判断​

  • 读取水位值，超过阈值进入警戒状态。

联动​

  • 警戒时升起警戒杆并显示提醒；恢复时按课堂规则复位。

3. 关键参数​

参数示例值含义调整建议
水位阈值待实机确认不直接假定对应厘米数以实测干湿读数确定
警戒/复位位置待实机确认与通行闸门的状态含义明确区分按模型校准
提示音频率待实机确认避免持续高频提醒按课堂需要设置
备注

水位传感器输出随接触水的状态变化，程序将读数与实验确定的阈值比较。读数不一定能直接换算成厘米。基础模型超阈值进入警戒，低于阈值恢复；真实道路封控还需要更多信息和人工管理，本模型仅用于教学演示。

警告

只让传感器允许接触水的部分接触水面，保持主控、电源与接线区域干燥。警戒状态应表达禁止通行。

运行测试​

完成程序后，按以下顺序测试：

  1. 启动检查：连接设备并下载已验证程序，确认初始化状态与屏幕标签正确。
  2. 探测部分干燥：显示正常，警戒杆处于复位位置。
  3. 逐渐增加允许接触水的面积：达到警戒条件后动作并提醒。
  4. 擦干并重新放置：记录复位行为，测试结束断电清洁。
  5. 复测与记录：改变一个条件后重复测试，记录输入、输出与结果；结束时停止执行器。

如果出现“无水时仍警戒”，检查残留水分、接线与阈值，重新记录干燥读数。

如果出现“水位变化但无响应”，检查探测区域、兼容接口和读取方式。

案例演示​

程序运行后，积水警戒闸门可以呈现以下效果：

  • 显示正常，警戒杆处于复位位置。
  • 达到警戒条件后动作并提醒。
  • 记录复位行为，测试结束断电清洁。

总结分享​

请各小组展示作品，并围绕以下问题进行交流：

  1. 你们记录了哪些数据？测试条件是否保持一致？
  2. 本案例使用了哪些判断规则或数据处理方法？
  3. 测试过程中出现了哪些结构或程序问题？你们是怎样解决的？
  4. 哪一项测试最能证明作品实现了预期功能？
  5. 如果继续改进，你们最想优化什么？为什么？

扩展挑战​

挑战一：增加分级水位提示​

根据实测读数划分正常、关注和警戒等级。为不同等级设置清晰的屏幕或灯光反馈。

挑战二：加入解除警戒条件​

设置独立的解除警戒条件，或要求水位持续下降后恢复。测试临界读数附近是否仍频繁切换。

挑战三：统计警戒时长​

记录进入警戒与解除警戒的时间，累计警戒时长。观察不同水位变化过程的差异。

挑战四：增加传感器异常提示​

在模块支持的情况下识别异常或无效读数。显示检查提示，避免将读数失败直接解释为无积水。

挑战五：设计声光联动​

让警戒图标、灯光和提示音表达同一状态。调节提醒间隔，避免连续提示影响课堂观察。

扩展知识​

水位读数代表什么？​

水位传感器返回与接触水面情况有关的数据。读数受安装位置、水质及传感器结构影响，未经标定不能直接当作厘米数。

警戒闸门怎样表达状态？​

模型应在积水时形成清晰的禁行提示。闸门的升降、开合或转动方向取决于结构，不能只根据“升起”一词认定通行状态。

为什么不能用于真实防灾？​

课堂模型用于理解感知与响应，未经过真实场景所需的可靠性、防水和安全验证。真实积水风险应由专业系统与人员处理。
